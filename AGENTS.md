# AGENTS.md

This repository is a pnpm monorepo of extensions for [Pi](https://pi.dev), the coding agent. The root holds shared tooling and documentation only. Every extension is a self-contained Pi package in `packages/<name>/`, published to npm as `@zeroclover/<name>`. All implementation is done by AI agents; this file and `docs/` are the contract they work from.

## Before you start

- Read the document that matches your task from the index below, completely, before editing.
- Load the `pi-extension-dev` skill (`.agents/skills/pi-extension-dev/SKILL.md`) whenever you create, change, or debug an extension.
- There is no fixed Pi version: extension work always targets Pi's latest stable release. Before creating, changing, or debugging an extension, check that the root pins it, and upgrade first if not, without a proposal (`docs/workflow.md`, "Track the latest Pi").
- Pi's API changes quickly. Answer every API question from the docs, examples, and type declarations of that version under `node_modules/@earendil-works/pi-coding-agent/` (see `docs/pi-reference.md`), not from memory.

## Rules

1. The root contains no extension runtime code. Root config files and `tools/` are shared development and CI tooling; change them only for repo-wide concerns and never to work around one package's problem.
2. One directory, one package. `packages/<name>/` must work on its own: `pi -e ./packages/<name>` loads it, and its `package.json` declares its own `pi` manifest and dependencies. Its npm name is always `@zeroclover/<name>`: directories, OpenSpec roots, and commit scopes use the bare `<name>`; change intents, `pnpm --filter`, the registry, and release tags use the full name.
3. Host-provided packages (`@earendil-works/pi-coding-agent`, `pi-ai`, `pi-tui`, `pi-agent-core`, `typebox`) go in `peerDependencies` with range `"*"`, never in `dependencies`. Pi supplies them at runtime; a bundled copy breaks its module mapping.
4. TypeScript is strict (`tsconfig.base.json`) and Biome enforces lint and format. Fix the code, not the rule: no `any`, no `@ts-ignore` or `@ts-expect-error`, no `biome-ignore` without a reason, no loosening of shared config.
5. Work is done only when verified: `pnpm check` passes (it also loads every extension in Pi), plus the live checks the change needs (`docs/workflow.md`, "Verify"). CI-only checks (`pnpm change check`, the release-impact gate, the artifact preflight) need no local run, and a release preparation is verified by its review and CI (`docs/releases.md`). Report what you ran, not what you assume.
6. Use pnpm exclusively. Never npm, npx, yarn, or bun.
7. Commits follow Conventional Commits with the package directory name as scope (`feat(pi-foo): add /foo command`); repo-wide changes use scope `repo`. Scopes carry no versioning meaning.
8. Keep each package's `README.md` and the extension table in the root `README.md` in sync with the code.
9. Agent configuration has one shared surface: this file and `.agents/`. `.claude/` is the only harness-specific directory (generated by `openspec init --tools claude,codex`; `codex` only produces the shared `.agents/skills`). Do not add files for any other harness, and keep `CLAUDE.md` exactly `@AGENTS.md`.
10. Non-trivial work goes through OpenSpec (propose, apply, archive). Package-scoped changes and specs live in `packages/<name>/openspec/`, repo-wide ones in the root `openspec/`. Run every `openspec` command with the matching directory as the working directory; the CLI uses the nearest root. See `docs/workflow.md`, "Plan with OpenSpec".
11. Releases follow `docs/releases.md`. Every change to a plugin's published content carries a release decision recorded with `pnpm change` in the same pull request: a positive intent, or `none` with a reason. Never edit versions, changelog version headings, or `.changeset/ledger.yaml` by hand. Preparing versions, merging a preparation, publishing, and dispatching a release each need an explicit request for that action; after an authorized merge, CI publishes and tags without further approval.

## Commands

Run from the repository root.

| Command | Purpose |
|---|---|
| `pnpm install` | Install tooling and host packages (needed for types, docs, and examples) |
| `pnpm check` | Lint, typecheck, test, and load every extension in Pi; the gate before every source commit |
| `pnpm lint:fix` | Apply Biome fixes and formatting |
| `pnpm typecheck` / `pnpm lint` / `pnpm test` | Individual steps of `check` |
| `pnpm --filter @zeroclover/<name> <script>` | Run a package's own script |
| `pnpm change --bump <patch\|minor\|major\|none> --summary "..." @zeroclover/<name>` | Record a release decision (`docs/releases.md`) |
| `pnpm change status` | Show pending release intents and the plan they produce |
| `cd packages/<name> && openspec <cmd>` | OpenSpec for one package (root `openspec` is for repo-wide changes) |
