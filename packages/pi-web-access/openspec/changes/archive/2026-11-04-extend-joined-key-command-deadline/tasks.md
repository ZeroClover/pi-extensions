## 2. The fix

- [x] 2.1 In `src/credentials.ts`, have `runCommand` return `{ result, extendDeadline }`, where `extendDeadline` calls `timer.refresh()` while the command runs and does nothing after it ended. `CredentialStore.keys` holds that pair, and `resolveKey` calls `extendDeadline` when it finds a pending key. Keep the second wait and `retry` in `resolve()`, and rewrite the branch's comment to say what it does now (`design.md`, "Keep the retry branch in `resolve()`"). A template key's `extendDeadline` is a no-op. `running` turns false when the timer fires as well as on `close` and `error`, and a comment says why: a fired timer would be reactivated by `refresh()` and signal a process group whose id may have been reused. Rewrite the comment above `runCommand` (`src/credentials.ts:77-82`), because "for at most `timeoutMs`" no longer holds. Verify that scenarios 1.1 to 1.4 now pass and the rest of `test/credentials.test.ts` still passes, including "runs a key command once per session" and the timed-out command scenario.
